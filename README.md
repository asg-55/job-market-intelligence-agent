# AI Job Search Copilot

Портфельный и прикладной проект: сервис мониторит вакансии через официальные API источников,
сравнивает их с профилем кандидата, сохраняет объяснимую оценку и отправляет лучшие новые
варианты в Telegram.

## Что уже работает

- несколько поисковых запросов к HH API и открытому Remotive API без HTML-парсинга;
- независимые статусы источников: сбой одной площадки не останавливает остальные;
- опциональные адаптеры SuperJob и Jooble активируются только локальными API-ключами;
- ручной импорт вакансий LinkedIn и других сайтов через кабинет или Telegram без парсинга;
- application token HH хранится только локально; CAPTCHA, OAuth и rate limit показываются как понятные статусы;
- получение полного текста вакансии и дедупликация;
- жёсткие фильтры по региону, формату, опыту, зарплате и стоп-словам;
- объяснимый скоринг роли, навыков и условий;
- опциональный structured LLM-анализ через Ollama/OpenAI-compatible API;
- история оценок в SQLite для будущих evals;
- история запусков мониторинга и локальный dashboard по источникам, оценкам и воронке;
- постоянно редактируемый профиль с hot reload и версионированием оценок;
- именованные профили поиска с несколькими HH-запросами и предпочтительным резюме;
- Telegram-карточка с кнопками и API для обратной связи;
- HTTP API и разовый CLI-запуск;
- тесты ключевой бизнес-логики и Docker-образ.

Продуктовые границы и метрики описаны в [docs/PRODUCT.md](docs/PRODUCT.md).
Подробная инструкция для первого запуска находится в [docs/SETUP_RU.md](docs/SETUP_RU.md).

## Быстрый старт

Для постоянной работы на Windows рекомендуется гибридный нативный режим: Python-ядро и n8n
работают как локальные процессы, а AI использует уже установленную Ollama. Пошаговая инструкция:
[docs/NATIVE_N8N_RU.md](docs/NATIVE_N8N_RU.md).

Docker остаётся воспроизводимым резервным способом запуска и средой проверок для GitHub.

### Резервный запуск в Docker

Для резервного способа работы требуется Docker Desktop.

```powershell
Copy-Item config/profile.example.json config/profile.json
Copy-Item .env.example .env
docker compose up --build -d copilot worker bot
```

Отредактируйте `config/profile.json` и обязательно замените контакт в `HH_USER_AGENT`.
Токен HH для публичного поиска не нужен. Для Telegram создайте бота через BotFather, напишите
ему сообщение и укажите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env`.

`copilot` поднимает HTTP API и пользовательский кабинет, `worker` запускает мониторинг сразу и
затем каждые 12 часов, а `bot` принимает команды и документы из Telegram.
Разовый ручной запуск тоже выполняется в контейнере:

```bash
docker compose run --rm worker job-copilot run --pages 1
```

### Локальная LLM в Docker

LLM необязательна: при пустом `LLM_MODEL` работает только детерминированный baseline. Чтобы
подключить Ollama и Qwen 3.5 9B:

```bash
docker compose --profile local-llm up -d ollama
docker compose exec ollama ollama pull qwen3.5:9b
```

После загрузки укажите `LLM_MODEL=qwen3.5:9b` в `.env` и перезапустите `copilot` и `worker`.
Модель получает только вакансию, навыки и подтверждённые факты профиля. Ответ проверяется
Pydantic-схемой, смешивается с baseline и сохраняется вместе с моделью и версией промпта.

После запуска доступны Swagger UI на `http://localhost:8000/docs` и методы:

- `POST /monitor/run` — выполнить мониторинг;
- `GET /monitor/runs` — показать историю запусков и их результаты;
- `GET /analytics/overview` — получить сводку для аналитического dashboard;
- `GET /vacancies` — показать ранжированные вакансии;
- `POST /vacancies/import` — сохранить и сразу оценить вручную добавленную вакансию;
- `GET`, `PUT`, `PATCH /profile` — читать и изменять живой профиль без перезапуска;
- `POST /vacancies/{id}/feedback` — сохранить `fit`, `skip`, `applied`, `rejected` или `interview`.

## Пользовательский кабинет

Откройте `http://localhost:8000/app`. Это основной интерфейс вместо ручного редактирования JSON
и Swagger: в нём можно менять профиль и пожелания, создавать и редактировать резюме, связывать
их с направлениями поиска и просматривать найденные вакансии. Кабинет адаптирован для телефона,
но по умолчанию доступен только на локальном компьютере.

В разделе вакансий кнопка `Подробнее` открывает рабочую область: объяснение оценки, совпавшие
и недостающие навыки, статус отклика, выбор базового резюме, рекомендации по его адаптации и
черновик сопроводительного письма. AI-действия становятся доступны после настройки `LLM_MODEL`;
исходное резюме сервис не перезаписывает.
На главном экране видны состояние всех источников, количество вакансий по площадкам,
распределение оценок и последние запуски вручную, из n8n, CLI или расписания. История хранится
в той же локальной SQLite-базе и не содержит секретов интеграций.

После получения рекомендаций кнопка «Создать рабочую копию резюме» сохраняет отдельный вариант,
связанный с исходной версией, вакансией и отчётом AI. Копия появляется в библиотеке, где её можно
отредактировать и скачать как DOCX. Любое резюме в библиотеке также можно экспортировать кнопкой
`DOCX`; в файл попадает только текущий текст документа, без внутренних заметок и аудита.

## Интерактивный Telegram-бот

Контейнер `bot` использует long polling, поэтому для локальной работы не нужен публичный webhook.
Доступные команды:

- `/add_resume` — пошагово добавить PDF, DOCX или TXT до 5 МБ;
- `/resumes` — показать активные резюме и версии;
- `/preferences` — сохранить пожелания обычным сообщением;
- `/profile` — показать краткий профиль;
- `/app` — получить ссылку на кабинет;
- `/cancel` — отменить текущий диалог.

Бот обрабатывает сообщения только от `TELEGRAM_CHAT_ID`, указанного в `.env`. Не запускайте long
polling и webhook одновременно. Кнопка Telegram Web App требует публичного HTTPS-адреса и будет
настроена отдельным безопасным этапом; локально `/app` сообщает адрес кабинета на компьютере.

Кнопки обратной связи в Telegram используют `POST /telegram/webhook`. Для них нужен публичный
HTTPS-адрес сервиса. Создайте случайный `TELEGRAM_WEBHOOK_SECRET`, затем зарегистрируйте URL:

```bash
curl -X POST "https://api.telegram.org/bot<TOKEN>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/telegram/webhook","secret_token":"<SECRET>"}'
```

В нативном режиме расписанием управляет импортируемый n8n workflow, который вызывает
защищённый HTTP API. В Docker-режиме интервал по-прежнему задаётся аргументом `--interval`
команды worker. Бизнес-логика остаётся в Python и не дублируется в оркестраторе.

## Как считается оценка

Сначала применяются обязательные ограничения. Затем итог складывается из навыков (55%),
соответствия роли (25%) и условий (20%). Провал жёсткого фильтра ограничивает оценку 39
баллами. Это baseline: его можно измерить на пользовательской обратной связи до подключения
более дорогого LLM/embedding-слоя.

## Профили поиска

Поле `search_profiles` разделяет мониторинг по направлениям. У каждого профиля есть стабильный
`key`, отображаемое имя, флаг `enabled`, собственный список запросов и необязательный `resume_id`.
Одна вакансия может встретиться сразу в нескольких направлениях: сервис сохранит все совпадения,
но оценит её и отправит уведомление только один раз. В Telegram показываются профиль первого
совпадения и рекомендуемое резюме. Старое поле `searches` продолжает работать, пока
`search_profiles` пуст.

## Безопасность и честность

Проект не делает автоматических откликов и не меняет основное резюме. Генератор писем
использует только `verified_facts` профиля и сохраняет черновик для проверки пользователем.
Секреты читаются из `.env`, который исключён из Git.

## Сопроводительные письма

При настроенной LLM сервис создаёт только черновик и никогда не отправляет отклик сам:

- `POST /vacancies/{id}/cover-letter` — создать письмо на русском или английском языке;
- `GET /cover-letters/{draft_id}` — получить сохранённый черновик и его аудит.

Перед генерацией заполните `verified_facts` в живом профиле. Каждый содержательный абзац
ссылается на конкретные подтверждённые факты; неизвестные ссылки модельного ответа отклоняются.
В SQLite сохраняются текст, версия профиля, модель, версия промпта и трассировка фактов. Статус
всегда `draft`: пользователь должен проверить письмо перед использованием.

## Рекомендации по резюме

- `POST /resumes` — добавить именованное базовое резюме для отдельного направления;
- `GET /resumes` и `GET /resumes/{id}` — получить библиотеку или конкретное резюме;
- `PUT /resumes/{id}` и `PATCH /resumes/{id}` — заменить или частично изменить его;
- `POST /vacancies/{id}/resume-advice` — сравнить выбранное резюме с вакансией;
- `GET /resume-advice/{advice_id}` — получить сохранённый отчёт.

Можно хранить несколько базовых вариантов, например `AI Product Engineer`, `Prompt Engineer`
и `AI Operations`. У каждого есть целевые роли, SHA-256 и номер версии, который увеличивается
при редактировании. Вместо удаления используется архивирование, поэтому история не теряется.

Сервис предлагает изменения только для отдельной адаптированной копии: фактологические пункты,
перестановки разделов, навыки для акцента и честно отмеченные пробелы. Текст библиотечного резюме
хранится в локальной SQLite-базе; в отчёт с рекомендациями повторная копия текста не записывается,
но сохраняются ID, версия и SHA-256. Для разового `resume_text` сохраняется только SHA-256.
Любой новый пункт обязан ссылаться на `verified_facts`, а рекомендованный навык уже должен
присутствовать в профиле.
Для анализа текст передаётся настроенной LLM: локальная Ollama оставляет его на компьютере,
а при облачном провайдере нужно учитывать его политику обработки персональных данных.

Источники API: [официальная документация HH](https://api.hh.ru/openapi/redoc),
[Remotive Remote Jobs API](https://github.com/remotive-io/remote-jobs-api) и
[SuperJob API](https://api.superjob.ru/), [Jooble API](https://help.jooble.org/en/support/solutions/articles/60001448238-rest-api-documentation),
[Telegram Bot API](https://core.telegram.org/bots/api). LinkedIn намеренно не собирается

сбор страниц запрещён правилами площадки. Пользователь может вручную перенести текст вакансии,
после чего все функции локальной оценки и подготовки материалов работают как обычно.
