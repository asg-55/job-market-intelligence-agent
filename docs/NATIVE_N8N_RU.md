# Нативный запуск Windows и n8n

В рабочем режиме проект использует лучшее из трёх компонентов:

- Python-приложение хранит профиль, резюме и вакансии, выполняет скоринг и создаёт DOCX;
- установленная в Windows Ollama запускает локальную `qwen3.5:9b`;
- n8n отвечает за расписание, наблюдаемость и сводку в Telegram.

Docker остаётся резервным способом запуска и средой CI, но для постоянной работы не требуется.

## 1. Требования

- Windows 10 или 11;
- Python 3.12 x64 с включённым `Add python.exe to PATH`;
- Node.js LTS;
- запущенная Ollama и установленная модель `qwen3.5:9b`.

Проверка Ollama без зависимости от `PATH`:

```powershell
curl.exe http://127.0.0.1:11434/api/tags
```

## 2. Установить локальное окружение

Из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\setup_native.ps1
```

Скрипт создаст изолированную `.venv`, установит Job Copilot и проверенную версию n8n 2.32.5.
Если в `.env` ещё нет внутреннего токена автоматизации, скрипт безопасно создаст его и не выведет
значение в терминал. Первая установка n8n занимает несколько минут из-за большого числа встроенных
интеграций.

## 3. Настроить `.env`

Нативные значения должны выглядеть так:

```dotenv
LLM_BASE_URL=http://127.0.0.1:11434/v1
LLM_API_KEY=ollama
LLM_MODEL=qwen3.5:9b
AUTOMATION_API_TOKEN=<длинная случайная строка>
```

`AUTOMATION_API_TOKEN` — отдельный секрет только для связи n8n с локальным API. Установщик создаёт
его автоматически. Не заменяйте его Telegram-токеном.

Если внутренний токен мог попасть в журнал или на скриншот, выпустите новый без переустановки окружения:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\setup_native.ps1 -ConfigureOnly -RotateAutomationToken
```

После ротации обновите значение в credential `Job Copilot Automation Token` и перезапустите приложение.

## 4. Первый запуск

Перед переключением остановите старые рабочие контейнеры, чтобы они не конкурировали за Telegram long polling и порт 8000:

```powershell
docker compose stop copilot worker bot
powershell -ExecutionPolicy Bypass -File scripts\windows\start_job_copilot.ps1
```

После запуска доступны:

- приложение: `http://127.0.0.1:8000/app`;
- n8n: `http://127.0.0.1:5678`;
- Ollama: `http://127.0.0.1:11434`.

Журналы создаются в игнорируемой Git папке `logs`, а локальная база n8n — в `data/n8n`.
Супервизор проверяет процессы каждые пять секунд и перезапускает завершившийся компонент.

## 5. Импортировать workflow n8n

1. Откройте n8n и создайте локального владельца.
2. Импортируйте `n8n/job-copilot-monitor.json`.
3. Создайте credential типа **Header Auth** с именем `Job Copilot Automation Token`:
   - Name: `X-Automation-Token`;
   - Value: значение `AUTOMATION_API_TOKEN` из `.env`.
4. Создайте credential типа **Telegram API** с именем `Job Copilot Telegram Bot` и новым токеном BotFather.
5. В узле `Send run summary` замените `REPLACE_WITH_TELEGRAM_CHAT_ID` на свой chat ID.
6. Выполните workflow вручную и проверьте сводку.
7. Активируйте workflow. Он будет запускать поиск каждые 12 часов.

n8n только вызывает защищённый endpoint. Найденные вакансии, резюме и персональные данные не сохраняются в workflow.

Если HH временно отвечает `403`, в том числе из-за проверки CAPTCHA, запуск не завершается аварийно:
сводка придёт с увеличенным счётчиком `errors`. Не повышайте частоту опроса и не пытайтесь обходить CAPTCHA;
дождитесь снятия ограничения или используйте официально разрешённый способ доступа к API HH.

## 6. Автозапуск

После успешного ручного теста:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\register_autostart.ps1
```

Задача стартует после входа пользователя в Windows. В параметрах электропитания отключите сон и гибернацию; блокировка экрана работе не мешает.

## Безопасность

- порты 5678 и 8000 слушают только `127.0.0.1`;
- не настраивайте проброс этих портов на роутере;
- `.env`, база, журналы и n8n credentials не публикуются в Git;
- Telegram продолжает принимать команды через исходящий long polling, поэтому публичный webhook не нужен.

n8n закреплён на проверенной версии 2.32.5. Эта версия поддерживает нативный запуск, однако n8n уже
предупреждает о планируемом переходе будущих версий на официальный Docker-образ. Поэтому не обновляйте
n8n вслепую: сначала проверяйте новую версию, а Docker-конфигурацию проекта сохраняйте как резерв.
